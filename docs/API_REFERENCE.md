# API reference

The site has one HTTP route handler for operations, one route handler for the RSS feed, and one server action. There is no public JSON API.

## `GET /api/health`

- **File:** `src/app/api/health/route.ts`
- **Rendering:** `force-dynamic`
- **Response:** `200 OK`, `application/json`

```json
{ "status": "ok" }
```

- **Used by:** the Docker `HEALTHCHECK`, the Compose health check, the Playwright `webServer` readiness probe, and CI.
- **Notes:** the route is excluded from crawling by `robots.txt` (`Disallow: /api/`).

## `GET /feed.xml`

- **File:** `src/app/feed.xml/route.ts`
- **Rendering:** `force-static` (generated at build time)
- **Response:** `200 OK`, `application/rss+xml; charset=utf-8`
- **Content:** RSS 2.0 channel for `siteConfig.name` with one `<item>` per published post from `getPublishedPosts()`. Drafts never appear.

## Server action: `sendContactMessage`

- **File:** `src/app/contact/actions.ts` (`"use server"`)
- **Invoked by:** `src/components/forms/contact-form.tsx` through `useActionState`
- **Signature:** `sendContactMessage(previous: ContactFormState, formData: FormData): Promise<ContactFormState>`

### Input (`FormData` fields)

| Field | Rules (Zod, `src/lib/contact.ts`) |
| --- | --- |
| `name` | trimmed, 2–100 characters |
| `email` | valid email (`z.email()`), ≤ 200 characters |
| `message` | trimmed, 20–4000 characters |
| `website` | honeypot; must be empty |

### Result type

```ts
type ContactFormState =
  | { status: "idle" }
  | { status: "success" }
  | { status: "error"; message: string; fieldErrors?: Partial<Record<"name" | "email" | "message", string>> };
```

### Behaviour, in order

1. If `RESEND_API_KEY`, `CONTACT_TO_EMAIL`, or `CONTACT_FROM_EMAIL` is missing → `error` "not configured". Nothing else runs. The `/contact` page also hides the form in this state.
2. Validate. If the honeypot has content → return `success` without sending (automated submitters learn nothing). Other validation failures → `error` with `fieldErrors`.
3. Rate limit: 3 submissions per 10 minutes per client key (`x-forwarded-for` first hop, then `x-real-ip`, then `"unknown"`). Exceeded → `error` "Too many messages".
4. Deliver through Resend (`from: CONTACT_FROM_EMAIL`, `to: [CONTACT_TO_EMAIL]`, `replyTo: sender`, plain text). Provider errors are logged server-side and returned as a generic `error`; provider messages are never surfaced to the client.
5. → `success`.

### Test coverage

`tests/unit/contact.test.ts` (schema, honeypot, rate limiter, config) and `tests/unit/contact-action.test.ts` (fail-closed, validation, honeypot, delivery payload, rate limit, provider failure) with `next/headers` and `resend` mocked.

## Not present

There are no REST or GraphQL endpoints, no authentication routes, no webhooks, and no admin API. Documented here so that nobody searches for them.
